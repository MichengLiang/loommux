[#package-status]
== 文档包状态

本文档包是已批准的第一阶段目标基线，不是“当前仓库已经实现这些行为”的运行状态声明。设计规格中的规范词约束第一阶段目标；当前 Python/IPython engine 的已实现行为仍由其代码和既有文档描述，直到相应迁移工作包通过验收。

因此，仓库中的主张必须带有可判定的时间坐标：

implemented baseline:: 描述审查时仓库已经运行的行为；不得被误写为 Pueue engine 的目标契约。
phase-one target:: 描述本文件夹规定、尚待工作包实现和验证的行为。
stale claim:: 在同一时间坐标和权威范围内已被替代，却仍无限定地宣称有效的表述。

Python/IPython engine 保留 Python callback workspace resolver；Rust/Pueue engine 使用 versioned TOML grammar。两者共享 workspace resolution 的观察分类，但各自使用适合 runtime 的配置文件语言。

[#authority-order]
== 权威关系

文档发生表述冲突时按对象 owner 判断，不按文件长度或修改时间判断：

. 系统行为以设计规格为准；
. 工程顺序和验收状态以交付计划为准；
. 文档写作与健康状态以文档质量标准为准；
. 外部事实以证据登记及其高优先级 source 为准；
. README、示例、tool description 和代码注释不得在同一时间坐标内定义相反行为；implemented baseline 与 phase-one target 必须明确标识，不能相互冒充。

证据与设计冲突表示设计前提失效，必须同时审查受影响决定；交付计划不能用 implementation convenience 覆盖设计规格。

[#key-conclusions]
== 核心结论

* `loommux-pueue` 是 Loommux 项目下以 Pueue 为 backend 的 execution engine；
* 第一阶段目标配对是 Pueue `4.0.4` 与 exact `pueue-lib 0.31.1`；
* 一个 stdio process 拥有一个 adapter-local execution namespace；
* 多个 adapter 可以连接同一个 Pueue daemon instance；
* execution 是唯一公共地址，Pueue task ID 是 private backend identity；
* 公共闭环由 `run_shell`、`status`、`execution_status`、`read_output`、`search_output`、`wait` 和 `cancel` 构成；
* Pueue combined task log 投影为 append-only combined transcript；
* wait deadline 只结束本次 observation，不改变 task；
* queued/stashed cancellation 与 running/paused kill 使用不同 backend operation 并保留不同 terminal state；
* adapter 不拥有 daemon，adapter close 不停止 task；
* 第一阶段只提供 stdio；HTTP 需要独立 session contract；
* 最终交付同时要求系统完成、系统优秀、文档完成和文档优秀。

[#health-checks]
== 健康检查

文档健康检查至少包含：

[source,sh]
----
# PlantUML deterministic generation
plantuml -tsvg -o ../images docs/pueue-engine/diagrams/*.puml

# Structured ID, xref, traceability, residue, scale and SVG drift audit
uv run --project ../.. python scripts/audit_pueue_engine_docs.py

# AsciiDoc parse/render with the workbench Node toolchain
pnpm --package=@asciidoctor/cli@4.0.0 dlx asciidoctor \
  --failure-level WARN -D tmp/pueue-engine-docs docs/pueue-engine/*.adoc

# Whitespace and patch integrity
git diff --check
----

以上命令从 `projects/loommux/` 执行。结构化审计脚本负责 ID uniqueness、xref resolution、token statistics、两张显式 traceability table、placeholder/chat residue、未关闭 claim marker、旧目标版本残留和 PlantUML/SVG 字节一致性；它只豁免质量规则中的受控反例以及 EVD-PUEUE-010 的历史版本比较。健康检查连续运行两次应产生相同结论和零 generated diagram diff。

[#acceptance-summary]
== 最终验收

[source,text]
----
RELEASE_PACKAGE_ACCEPTED =
    ENGINE_ACCEPTED
    AND DOCUMENTATION_ACCEPTED
    AND all cross-references resolve
    AND generated diagrams are current
    AND repository-wide unqualified stale claims are zero
----

该公式评价第一阶段发布包，不把目标文档已经写成等同于 engine 已经交付。任何需要主要作者口头补充才能成立的规则、理由、来源或验收条件，都表示发布包尚未通过最终验收。
