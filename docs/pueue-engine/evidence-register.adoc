[#evidence-policy]
== 证据政策

[#evidence-authority]
=== 证据与设计的关系

证据回答“对象实际上具有何种行为”或“某次运行观察到了什么”。xref:design-specification.adoc#document-authority[设计规格]回答“Loommux 因此定义何种公共契约”。证据不能跳过设计推导直接成为工具 surface，设计也不能在没有证据的情况下声称外部 library 或 daemon 具有某种行为。

每个 evidence record 使用稳定 `EVD-*` ID。记录至少包含：

Source:: repository、version/tag/commit、file/symbol 或本地路径。
Observation:: 可从 source 或 experiment 得到的事实。
Scope:: 事实成立的版本、环境和边界。
Supports:: 使用该事实的设计决定、规范章节或交付要求。
Does not prove:: 防止证据被扩张解释的限定。
Verification:: 复现 source lookup 或 runtime observation 的方法。

[#source-priority]
=== 来源优先级

发生冲突时按以下顺序处理：

. 当前目标版本的 upstream source 和 protocol types；
. 当前 Loommux 代码、测试和已生效公共 contract；
. 在固定版本环境中可重复的真实运行实验；
. upstream 官方版本化文档；
. 当前 crates.io package metadata；
. 原始聊天和调研笔记。

较低优先级来源不能覆盖较高优先级事实。source 与 runtime observation 冲突时，必须先确认实际运行 binary、library 和配置版本；不能选择更符合预期的一方。

[#evidence-status]
=== 记录状态

`verified`:: 已定位 source 或完成可重复实验，可支持 current design。
`bounded`:: 事实已验证，但仅适用于明确版本或 local-daemon 边界。
`superseded`:: 记录曾出现在讨论中，但被更高优先级证据或后续决定替代。
`historical`:: 只用于解释需求来源，不支持外部技术事实。

G0 后，不允许 `unverified` evidence 支持 normative design。版本升级时，所有与目标版本绑定的记录必须重新验证并更新日期。

[#evidence-pueue-wait]
=== EVD-PUEUE-003：Pueue wait 是 client-side state polling

Status:: verified

Source::
https://github.com/Nukesor/pueue/blob/v4.0.1/pueue/src/client/commands/wait.rs[`pueue/src/client/commands/wait.rs`] 中 `wait` 和 `reached_target_status`；`pueue_lib/src/message/request.rs` 中 `Request` enum。

Observation::
`Request` 没有 Wait variant。CLI `wait` 重复调用 `get_state(client)`，比较 task status，并在普通环境休眠 2,000 ms；测试环境使用 250 ms。默认 target 是 Done，Success target 对失败 task 退出 1。

Scope::
两秒是目标 CLI 实现的 polling interval，不是 daemon protocol promise。Loommux 增加自己的 monotonic deadline 和 response semantics。

Supports::
xref:design-specification.adoc#wait-tool[`wait`]、DEC-PUEUE-008、WP-06。

Does not prove::
一次 Pueue wait 返回表示 shell success；Done 仍需检查 TaskResult。

Verification::
`git show v4.0.1:pueue/src/client/commands/wait.rs` 并检索 `get_state`、`sleep_time`。

[#evidence-pueue-cancel]
=== EVD-PUEUE-007：Kill 与 Remove 的状态边界

Status:: verified

Source::
`pueue_lib/src/message/request.rs` 中 `KillRequest`、`TaskSelection` 和 `Request::Remove`；`pueue/src/daemon/network/message_handler/kill.rs`；`pueue/src/daemon/process_handler/kill.rs`；remove handler。

Observation::
task-ID kill response helper 只接受 `Task::is_running`，即 Running 或 Paused task。Kill selection 可以是 TaskIds、Group 或 All；无 signal 的 task-ID kill 进入 daemon child kill logic。Remove 用于非 running/paused task，并从 state 删除 task。

Scope::
Loommux 使用 `TaskIds([task_id])`，不使用 group/all。queued/stashed remove 后的 public cancelled record 由 adapter 保留，是 Loommux 设计语义。虽然 Pueue remove handler 接受 locked task，Loommux 在公共 `cancel` 契约中对 locked 返回 `cancel_blocked`，以避免破坏其他 client 正在进行的三步编辑协议。

Supports::
xref:design-specification.adoc#cancel-tool[`cancel`]、xref:design-specification.adoc#dec-pueue-009[DEC-PUEUE-009]、WP-06。

Does not prove::
Kill success response 表示 task 已经进入 Done/Killed；仍需后续状态观察。

[#evidence-maintenance]
== 维护规则

版本、source file 或 public design 变化时：

. 先更新或新增 evidence record；
. 标明旧 evidence 的 bounded/superseded 状态，不复用 ID 表示另一事实；
. 重新审查受支持的 `DEC-PUEUE`、规范章节、WP、VER 和 gate；
. 运行对应 source lookup、runtime experiment 和 document health checks；
. 在同一变更中更新 snapshot date 与版本矩阵；
. 不删除仍被历史决定引用的 evidence，除非提供 replacement xref。

evidence register 不保存 secret、完整 environment、用户私有配置正文或不可公开日志。需要证明敏感配置行为时，使用合成 fixture 和脱敏输出。
